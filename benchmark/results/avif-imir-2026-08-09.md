# AVIF `imir` decode evidence (2026-08-09)

## Scope

This run validates AVIF item mirroring through `imir`, including property validation,
`irot` composition, integer `clap` cropping, image grids, alpha auxiliaries, pipeline
auto-orientation, and browser execution. The portable decoder continues to emit ordered
row blocks; mirroring uses the existing pipeline orientation transform rather than a
second source-sized RGBA frame.

## Fixtures

All three files are deterministically generated with libavif 1.3.0, libaom 3.12.1,
one encoder worker, full-range identity-color YUV 4:4:4, and checksum-pinned PNG input.

| Fixture | Transform subset | Portable output | Portable RGBA SHA-256 |
| --- | --- | ---: | --- |
| `libavif-imir-axis0-160x160.avif` | `imir=0` (top-to-bottom) | 160x160 | `ecc5d7baa51289462eb57ed3e9e2202872d4e24438849531f15b04d0d1d8cc8a` |
| `libavif-imir-axis1-160x160.avif` | `imir=1` (left-to-right) | 160x160 | `150d389f0f9ec73685c3b301933f344e68d045114e96b06d4e09c2ae2d056569` |
| `libavif-imir-clap-irot-grid-alpha-160x160.avif` | 2x2 color and alpha grids, integer `clap`, `irot=1`, `imir=1` | 96x112 | `b3cca86fed0bf074641663fea9611be3ed3a217498b0095864300df265acf533` |

The first two portable outputs are byte-identical to the deterministic mirrored source,
Sharp/libvips, and Chromium. The combined grid/alpha output is byte-identical to the
deterministic source after crop, rotation, and mirroring.

## Independent decoders

Versions:

- `avifdec`/`avifenc` 1.3.0 with dav1d 1.5.1 and libaom 3.12.1
- Sharp 0.35.3 with libvips 8.18.3 and libheif 1.23.1
- Chrome 150.0.0.0 through the harness browser device

Both `avifdec --codec dav1d` and `avifdec --codec aom` produced byte-identical raw RGBA
for every fixture. The two opaque axis files share raw RGBA SHA-256
`b4048af1aed5ab360fb12c9bec09be99449654505f02de4d55508384346161da`.
The combined grid/alpha file has raw 160x160 RGBA SHA-256
`6732741c04252940e9a95d6df2939b39a37f94011b35ea08ac1495617f0b2e75`.
Libavif intentionally reports that `clap` and orientation are not applied by `avifdec`;
the verifier separately checks PureJsImage's composed output against the deterministic
source pixels.

Sharp matched both opaque mirrored outputs byte for byte. For the combined grid/alpha
fixture, Sharp produced 96x112 RGBA SHA-256
`ad7191664c5c2a2a42c8e95d9bd07e36cb0fc0ba1ae4e479f3c234b579dbb1dd`, which differs
from the deterministic composed output. This observation is pinned; no compatibility
claim is made for Sharp's combined grid-item transform behavior.

Chromium matched both opaque mirrored outputs byte for byte. For the combined fixture,
Chromium's native AVIF decoder returned the untransformed 160x160 image with RGBA SHA-256
`5f22a0d268ac2f295e8c8d2fbaa90267a04ea03f5597eb782cf4210738ee9d1f`; it did not apply
the dimension-changing grid `clap`/orientation properties. The browser compatibility
workflow pins both Chromium's native result and PureJsImage's 96x112 composed output so
that either behavior changing is explicit.
