# JPEG XL lossy recovery: evaluation amendment and diagnostic loop

Reviewed branch head: `5c20ef8f6238077c0e6f38a171a48d40f23709e3`. The retained public lossy encoder is still the implementation at `30d72d1a88a33e156fc6ed053c308d7268f4188d`. This stage changes evaluation tools and records no production codec change. Lossy remains Experimental.

## Evaluation decision

| Question | Finding and decision |
| --- | --- |
| What do the frozen protocols require? | [The original protocol](m7-evaluation-protocol.json) and [the approved 2 MP amendment](m7-bounded-quality-protocol.json) require measured, nondominated curves, no extrapolation, all missing bands visible, all 240 sources and original family splits retained, plus eight separate original-size checks. They do not explicitly require every source/reference pair to reach every 70/80/90 band. |
| What changed in later target tables? | [Prompt 9](m7-prompt9-report.md) and [Prompt 10](m7-prompt10-report.md) treated complete brackets as a Stable promotion gate. That interpretation is recorded as an additional gate, not silently attributed to the frozen protocols. No Stable decision follows from correcting the wording. Aggregate and class size limits, original-size checks, HDR/alpha views, runtime and resource limits remain in force. |
| What does the native high-band control establish? | [Ten pinned native streams](m7-recovery-ceiling-controls.json) still score below 90 at effort 7, distance 0.05 in the original RGB8 PPM pipeline. All ten normalized sources score 100 against themselves. Their pinned original files have the recorded SHA-256 and geometry, sRGB color space, no embedded profile, and no stored orientation; the normalized PPM and decoder output are both RGB8 at the same dimensions. For `im26-6834`, native and Rust independently decode a distance-0 lossless stream to the exact source pixels; the RGB8 PPM and PNG controls score 100. This is a tested-setting and RGB8-scoring ceiling. The earlier 0.02/0.05 byte-identical controls constrain this pinned API setting. It does not prove a JPEG XL format ceiling. |
| Can 16-bit PNG replace the RGB8 score? | No. The pinned `djxl --bits_per_sample=16` PNG declares 16-bit RGB but stores values only through 255 on the tested RGB8 source. The pixel-lossless control then scores 90.455729, while its RGB8 PPM and PNG score 100. The same lossy stream appears to cross 90 as PNG16 (90.100476 versus 89.789474 as PPM8), so that route fails its own control. The original RGB8 result is preserved. A different rendering/metric protocol would need its own version and identical treatment for both engines. |
| How are missing comparisons handled now? | [The per-target classification](m7-recovery-classification.json) keeps all 240 cases and all 720 SSIMULACRA2 target comparisons. A reference setting limit is neither a PureJsImage failure nor a pass. The 3-point bracket-width limit is a development diagnostic for judging small rate changes, not a retroactive change to the approved six-distance matrix. |

The classification counts are 81 measured comparisons with both brackets at most three SSIMULACRA2 points wide, 623 needing closer samples or an endpoint, six first-party 90 targets below its tested public distance floor, and ten reference 90 targets below the pinned native tested floor. There are no unsupported or execution/correctness failures in these 720 retained comparisons. All 240 score-70 and all 240 score-80 comparisons need tighter sampling under this diagnostic width. The original six-distance matched counts remain development 57/112/106 and observed holdout 65/114/112 at 70/80/90; the new width category does not rewrite them. The observed holdout has been inspected and is regression evidence.

The representative [first-party](../../../.tmp/jpegxl-m7/recovery-refine/stage-a-1030-own/report.json) and [native](../../../.tmp/jpegxl-m7/recovery-refine/stage-a-1030-native/report.json) development photo `im26-1030` refinements reached score-70 bracket widths 2.186 and 2.693. Their interpolation is 100,252 and 84,101 bytes, ratio 1.192 for this one source. Five new first-party and one native stream passed independent native/Rust decoding; the first-party streams also passed the repository decoder. This is a small diagnostic, not a new corpus ratio. Both [bounded receipts](../../../.tmp/jpegxl-m7/bounded-runs/stage-a-refine-1030-own-resume.json) and [the native receipt](../../../.tmp/jpegxl-m7/bounded-runs/stage-a-refine-1030-native.json) report zero swap. The [ceiling-control receipt](../../../.tmp/jpegxl-m7/bounded-runs/stage-a-ceiling-controls-v2.json) also reports zero swap. New runs use the existing isolated process-tree guard; metric memory does not change encoder limits.

Run a single development case with the reusable adaptive command:

```sh
node benchmark/jpegxl/run-m7-bounded.ts unique-run-id node benchmark/jpegxl/refine-m7-recovery.ts diagnostic-id development im26-1030 purejsimage 70 6 3
```

The command checks the normalized source hash, codec and tool hashes, and cached stream hashes before reuse. It selects at most six endpoints for one source and engine, checks monotonicity, retains nondominated measured points, and stops at a narrow bracket, the configured search limit, or the tested setting floor. It writes every new stream, score, Butteraugli value and independent-decoder result under `.tmp/jpegxl-m7/recovery-refine/diagnostic-id/`. Run the native comparator separately with the same input, target and width. The [read-only classifier](../classify-m7-recovery.ts) reproduces the full coverage table without encoding anything. The supplementary low- and high-endpoint reports and the approved matrix remain separate.

## Stage decision

No production behavior, capability manifest, package version, public lossy status, or historical result has changed. The original measured size and reference-host speed results in [Prompt 9](m7-prompt9-report.md) remain applicable to unchanged encoder paths. They pass their reported bounds only on measured brackets. The 623 wide or missing diagnostic comparisons and the five visual targets prevent a new Stable claim. The next stage can retain correct larger-transform machinery behind an experimental development path, then measure policy decisions against this diagnostic loop. A later Stable scope needs an explicit capability decision after visual, correctness, resource, browser and final qualification evidence; no all-source/all-band reference requirement is silently assumed.
