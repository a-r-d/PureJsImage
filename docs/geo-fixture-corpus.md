# Geo fixture corpus

## Quick Answer

The geo tests use a deterministic corpus described by
[`tests/fixtures/geo/manifest.json`](../tests/fixtures/geo/manifest.json). Small TIFF and BigTIFF
assets are checked in. Zarr stores, companion sets, ASCII data, sparse HGT tiles, and classic
NetCDF files are built in memory so tests can cover malformed sizes and large logical objects
without adding large binary files.

## Generation model

Each catalog entry names its source, materializer, coverage profiles, and development oracle. The
catalog test verifies that every source exists and that the combined entries cover every public geo
format, north-up and rotated geometry, negative Y resolution, area and point registration,
representative integer and floating samples, multiscale and multidimensional layouts, and malformed
inputs.

- GeoTIFF and COG fixtures are generated by `scripts/generate-cog-fixtures.ts`. The checked manifest
  records their hashes and layout facts.
- GeoZarr fixtures use the repository Zarr metadata, chunk, and shard builders. Official convention
  examples are pinned in `tests/fixtures/geozarr-conventions/SOURCES.md`.
- World-file, ENVI, Esri ASCII Grid, and HGT fixtures are built from fixed strings and typed arrays
  in `tests/geo-contained-readers.test.ts`. Sparse HGT sources have exact standard logical sizes
  without storing multi-megabyte zero-filled files.
- CDF-1 and CDF-2 fixtures use `tests/helpers/netcdf-classic-fixture.ts`. The helper writes checked
  big-endian headers, padding, record layouts, and data offsets.

## Development oracles

GDAL, Rasterio, xarray, SciPy NetCDF tooling, and official GeoZarr examples may be used to generate
or compare fixtures. They are development tools only and are not runtime dependencies. Oracle
output must be reduced to bounded fixture facts such as shape, affine, CRS evidence, registration,
sample values, nodata, and selected chunk or tile identity. The repository test remains the
executable compatibility claim.

## Updating the corpus

Add a catalog entry with a stable ID, deterministic materializer, profiles, and oracle note. Add or
update the focused reader test in the same change. Run `npm run capabilities:generate`, the focused
test, and `npm run check`. Never promote a fixture-limited capability to tested until the new corpus
exercises the missing boundary.
