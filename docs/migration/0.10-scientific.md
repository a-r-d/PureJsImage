# ScientificDataset in 0.10

`ScientificDataset` replaces positional XYZCT assumptions with labeled axes and is the only
public scientific dataset contract. The scientific API had no published consumers, so the alpha
removes the fixed-axis dataset surface instead of launching two competing models. Ordinary
`purejsimage` image workflows, including `resize().jpeg()`, remain unchanged.

## Request syntax

```ts
// Before
legacy.readPlane({ z: 2, c: 1, t: 0, x: 0, y: 0, width: 256, height: 256 })

// After
dataset.readPlane({
  displayAxes: ['x', 'y'],
  fixedIndices: [
    { axisId: 'z', index: 2 },
    { axisId: 'channel', index: 1 },
    { axisId: 'time', index: 0 },
  ],
  x: 0, y: 0, width: 256, height: 256,
})
```

Every non-displayed, non-singleton axis requires an explicit fixed index. Axis array position is not
semantic.

## Dataset mappings

| Domain | Scientific axes | Notes |
| --- | --- | --- |
| ordinary plane | `x(space), y(space)` | lossless in both directions when one component is stored |
| OME XYZCT | `x, y, z, channel, time` | preserves familiar IDs while making kinds/calibration explicit |
| FITS N-D | IDs derived from HDU axis metadata | arbitrary rank remains available without flattening it into XYZCT |
| EELS spectrum image | `x, y, energy(spectral)` | energy remains an independently selectable axis, not an RGB channel |
| 4D-STEM | `scanX, scanY, kx, ky` | scan and diffraction axes remain distinct; no flattening to Z/C/T |

Examples:

```ts
const eelsPlane = await read({
  displayAxes: ['x', 'y'], fixedIndices: [{ axisId: 'energy', index: 37 }],
})

const diffraction = await read({
  displayAxes: ['kx', 'ky'],
  fixedIndices: [{ axisId: 'scanX', index: 12 }, { axisId: 'scanY', index: 9 }],
})

const scanMap = await read({
  displayAxes: ['scanX', 'scanY'],
  fixedIndices: [{ axisId: 'kx', index: 64 }, { axisId: 'ky', index: 64 }],
})
```

## Parser migration boundary

The old fixed-axis parser objects and their adapters are internal implementation details while the
first-party parsers are moved to native `ScientificDataset` storage. They are not exported from a package entry and
must not be used by applications or new reader implementations. Compatibility tests may import the
internal helpers only to protect byte parsing during that migration.

## API and package changes

- Existing root and browser entries, `resize().jpeg()`, and ordinary format codecs are unchanged.
- Portable contracts and the explicit scientific library use `purejsimage/scientific`.
- First-party readers use individual `purejsimage/scientific/readers/*` entries; applications may
  deliberately import `purejsimage/scientific/readers/all` when they need every reader.
- Applications open GSF, ENVI, FITS, MRC, CBF, and OME-TIFF through registered readers and receive a
  `ScientificDocument` whose datasets are `ScientificDataset` values.
- browser File/Blob contexts use `purejsimage/scientific/browser`.
- Node path contexts use `purejsimage/scientific/node`; this subpath is intentionally Node-only.
- descriptors/providers use `purejsimage/operations`; graphs/results/ROIs/runtime use
  `purejsimage/analysis`; trusted bundles use `purejsimage/extensions`.

All new application entries are explicit and create no global registry, cache, Worker, or network
activity on import. Because the package is alpha, the scientific contract may still receive reviewed breaking cleanup
before the next published version increment. Every published version remains governed by its own
documented contracts and migration notes.
