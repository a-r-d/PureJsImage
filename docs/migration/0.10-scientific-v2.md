# Migrating to ScientificDataset V2 in 0.10 alpha

`ScientificDataset` V2 replaces positional XYZCT assumptions with labeled axes. It is additive and
opt-in: ordinary `purejsimage` image workflows and existing format open functions remain unchanged.
The fixed-axis `MultidimensionalRasterDataset` remains available as a deprecated bridge through the
0.9.x line and during the 0.10 alpha migration. No 1.0 removal date is promised yet.

## Request syntax

```ts
// Before
legacy.readPlane({ z: 2, c: 1, t: 0, x: 0, y: 0, width: 256, height: 256 })

// After
dataset.readPlane({
  displayAxes: ['x', 'y'],
  fixedIndices: [
    { axisId: 'z', index: 2 },
    { axisId: 'channel', index: 1 },
    { axisId: 'time', index: 0 },
  ],
  x: 0, y: 0, width: 256, height: 256,
})
```

Every non-displayed, non-singleton axis requires an explicit fixed index. Axis array position is not
semantic.

## Dataset mappings

| Domain | V2 axes | Notes |
| --- | --- | --- |
| ordinary plane | `x(space), y(space)` | lossless in both directions when one component is stored |
| OME XYZCT | `x, y, z, channel, time` | preserves familiar IDs while making kinds/calibration explicit |
| FITS N-D | IDs derived from HDU axis metadata | arbitrary rank remains V2-only unless it truthfully maps to XYZCT |
| EELS spectrum image | `x, y, energy(spectral)` | energy remains an independently selectable axis, not an RGB channel |
| 4D-STEM | `scanX, scanY, kx, ky` | scan and diffraction axes remain distinct; no flattening to Z/C/T |

Examples:

```ts
const eelsPlane = await read({
  displayAxes: ['x', 'y'], fixedIndices: [{ axisId: 'energy', index: 37 }],
})

const diffraction = await read({
  displayAxes: ['kx', 'ky'],
  fixedIndices: [{ axisId: 'scanX', index: 12 }, { axisId: 'scanY', index: 9 }],
})

const scanMap = await read({
  displayAxes: ['scanX', 'scanY'],
  fixedIndices: [{ axisId: 'kx', index: 64 }, { axisId: 'ky', index: 64 }],
})
```

## Adapter guarantees

`toScientificDataset(legacy)` is lazy and lossless for the legacy contract. It maps sizes to
`x/y/z/channel/time`, preserves sample/no-data/channel/calibration fields, and stores legacy
compatibility metadata. It does not materialize pixels.

`toMultidimensionalRasterDataset(v2)` succeeds only when the descriptor has spatial `x` and `y`,
optional spatial `z`, optional channel/spectral `channel`, optional time `time`, exactly one stored
component, and metadata/calibration representable without loss. It rejects arbitrary IDs/rank,
multi-component samples, incompatible axis kinds, lookup/labeled semantics that cannot map, and
additional typed metadata that the flat legacy record would discard. Rejection is preferable to
relabeling or flattening scientific meaning.

## API and package changes

- Existing root and browser entries, `resize().jpeg()`, format codecs, and legacy open functions are
  unchanged.
- V2 contracts/readers/adapters use `purejsimage/scientific`.
- browser File/Blob contexts use `purejsimage/scientific/browser`.
- Node path contexts use `purejsimage/scientific/node`; this subpath is intentionally Node-only.
- descriptors/providers use `purejsimage/operations`; graphs/results/ROIs/runtime use
  `purejsimage/analysis`; trusted bundles use `purejsimage/extensions`.

All new application entries are explicit and create no global registry, cache, Worker, or network
activity on import. Because the package is alpha, V2 may still receive reviewed breaking cleanup
before the next published version increment. Every published version remains governed by its own
documented contracts and migration notes.
